## 1. What
`.gitignore` là một file văn bản đặc biệt nằm trong thư mục gốc của repository, chứa danh sách các mẫu (patterns) tên file hoặc thư mục mà Git nên bỏ qua và không theo dõi (track).

## 2. Why
Trong dự án luôn có những file không nên hoặc không cần thiết phải đưa lên kho lưu trữ, ví dụ: các file chứa mật khẩu (`.env`), các thư mục thư viện nặng (`node_modules`), các file tạm của hệ điều hành (`.DS_Store`) hoặc kết quả biên dịch (`dist/`, `target/`). Nếu không có `.gitignore`, repository sẽ bị phình to và lộ thông tin nhạy cảm.

## 3. Mental Model
Hãy tưởng tượng Git như một người nhiếp ảnh gia đang chụp ảnh căn nhà của bạn. `.gitignore` giống như một bản danh sách những thứ bạn yêu cầu nhiếp ảnh gia "đừng chụp vào" (như thùng rác, tài liệu cá nhân trên bàn). Khi đó, bức ảnh cuối cùng (commit) sẽ chỉ chứa những gì đẹp nhất và cần thiết nhất.

## 4. Where it fits
Nằm ở bước đầu tiên của quy trình:
Files created -> .gitignore filtering -> Git status -> Git add.

## 5. When to use
- Phải tạo ngay lập tức khi khởi tạo dự án (`git init`).
- Khi thêm các thư viện mới hoặc công cụ mới sinh ra các file tạm.
- Khi làm việc với các framework (Spring Boot, React, Node.js) luôn có sẵn template `.gitignore` tiêu chuẩn.

## 6. When NOT to use
- Không dùng `.gitignore` để "xóa" một file đã lỡ commit và push lên server (phải dùng `git rm --cached` trước).
- Không dùng để bỏ qua các file cấu hình quan trọng mà cả team cần dùng chung.

## 7. Trade-offs
| Pros | Cons |
|------|------|
| Giữ repository sạch sẽ và nhẹ | Nếu cấu hình sai có thể bỏ sót file quan trọng |
| Bảo mật thông tin nhạy cảm (secrets) | Không có tác dụng với các file đã bị track từ trước |

## 8. Alternatives
| Option | So sánh |
|--------|---------|
| `git rm --cached` | Dùng để bỏ theo dõi file nhưng vẫn giữ lại file ở máy cục bộ (bổ trợ cho .gitignore). |
| Global gitignore | Cấu hình bỏ qua các file cho tất cả dự án trên máy (như file của IDE). |

## 9. How
Ví dụ một file `.gitignore` tiêu chuẩn:
```text
# Dependency directories
node_modules/
/target/

# Environment variables
.env
.env.local

# IDE files
.idea/
.vscode/
*.swp

# OS generated files
.DS_Store
thumbs.db

# Logs
*.log
```

## 10. Production concerns
### Scaling
Với các dự án monorepo (nhiều dự án nhỏ trong một repo lớn), mỗi thư mục con có thể có file `.gitignore` riêng để quản lý đặc thù cho từng module.

### Failure
Nếu lỡ commit file nhạy cảm dù đã có `.gitignore`, phải thực hiện quy trình "nuke" lịch sử bằng `git filter-repo` hoặc BFG Repo-Cleaner vì file đó vẫn tồn tại trong các commit cũ.

### Monitoring
Sử dụng các công cụ như `git check-ignore -v <file_path>` để kiểm tra xem một file đang bị bỏ qua bởi dòng nào trong `.gitignore`.

## 11. Common mistakes
- Mistake: Thêm file vào `.gitignore` sau khi đã lỡ commit nó.
  Fix: Chạy `git rm --cached <file>` rồi mới commit lại.

- Mistake: Viết sai đường dẫn hoặc pattern (ví dụ: thiếu dấu `/` ở cuối thư mục).
  Fix: Kiểm tra kỹ các quy tắc pattern matching (glob patterns) của Git.

## 12. Sample project
Tạo một file `secret.txt`, thêm vào `.gitignore`, sau đó chạy `git status` để xác nhận Git không nhìn thấy file đó nữa.

## 13. Interview
### Core Q&A
1. Q: Nếu tôi đã lỡ commit file `node_modules`, bây giờ tôi thêm nó vào `.gitignore` thì Git có tự động xóa nó khỏi lịch sử không?
   A: Không. `.gitignore` chỉ có tác dụng với những file chưa bị theo dõi (untracked). Để sửa, bạn phải dùng `git rm -r --cached node_modules`, sau đó commit thay đổi đó.

2. Q: Làm thế nào để Git bỏ qua một file nhưng vẫn giữ nó trên máy của mình?
   A: Đó chính là tác dụng của `git rm --cached`. Lệnh này xóa file khỏi index của Git nhưng không xóa file vật lý trên ổ cứng.

### Scenario
Tình huống: Bạn clone một dự án về và thấy thiếu file `.env` nên code không chạy được. Tại sao?
Trả lời: Vì file `.env` thường chứa thông tin nhạy cảm và đã được đưa vào `.gitignore` để không bị push lên GitHub. Bạn cần yêu cầu đồng nghiệp gửi file mẫu hoặc hướng dẫn cấu hình môi trường.
