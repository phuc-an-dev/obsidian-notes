## 1. What
AWS S3 (Simple Storage Service) là một dịch vụ lưu trữ đối tượng (object storage) được thiết kế để lưu trữ và truy xuất bất kỳ lượng dữ liệu nào từ bất cứ đâu trên internet. Nó cung cấp độ bền (durability), tính sẵn sàng (availability) và khả năng mở rộng (scalability) cực cao.

## 2. Why
Trước khi có object storage, dữ liệu thường được lưu trữ trong block storage hoặc file systems, vốn khó mở rộng quy mô lớn và tốn kém khi lưu trữ lượng dữ liệu khổng lồ (như video, ảnh, backup). S3 ra đời để cung cấp giải pháp lưu trữ rẻ tiền, không giới hạn dung lượng và có thể truy cập qua HTTP API.

## 3. Mental Model
Hãy tưởng tượng S3 như một kho lưu trữ đồ đạc khổng lồ không có giới hạn diện tích. Mỗi món đồ bạn gửi vào kho được đặt trong một chiếc hộp (Object), và mỗi chiếc hộp được gán một cái nhãn duy nhất (Key). Bạn không cần biết món đồ nằm ở kệ nào hay tầng nào, bạn chỉ cần đưa nhãn cho nhân viên kho (API) và họ sẽ mang món đồ đó ra cho bạn ngay lập tức.

## 4. Where it fits
Application/User -> HTTP(S) Request -> **AWS S3 Bucket** -> Objects -> Versioning/Life Cycle Policies.

## 5. When to use
- Lưu trữ tài nguyên tĩnh cho website (Images, JS, CSS).
- Lưu trữ các bản sao lưu (Backup) và lưu trữ dữ liệu lịch sử (Archive).
- Làm "Data Lake" cho các ứng dụng phân tích dữ liệu lớn.
- Hosting các trang web tĩnh (Static Website Hosting).
- Lưu trữ logs của hệ thống.

## 6. When NOT to use
- Khi cần lưu trữ dữ liệu thay đổi liên tục và yêu cầu độ trễ cực thấp (nên dùng EBS).
- Làm hệ điều hành hoặc cài đặt phần mềm trực tiếp (nên dùng EBS hoặc Instance Store).
- Khi cần cấu trúc file system truyền thống có tính năng locking (nên dùng EFS).

## 7. Trade-offs
| Pros | Cons |
|------|------|
| Độ bền lên tới 99.999999999% (11 nines) | Độ trễ (latency) cao hơn so với block storage |
| Dung lượng lưu trữ không giới hạn | Chi phí truy xuất dữ liệu (Data Retrieval) có thể cao |
| Tích hợp bảo mật mạnh mẽ (IAM, Bucket Policy) | Tính nhất quán (Consistency) có thể gây nhầm lẫn trong quá trình ghi/đọc đồng thời |

## 9. How
Upload một file lên S3 bằng AWS CLI:
```bash
# Tạo bucket
aws s3 mb s3://my-unique-bucket-name

# Upload file
aws s3 cp document.pdf s3://my-unique-bucket-name/docs/document.pdf

# List objects
aws s3 ls s3://my-unique-bucket-name --recursive
```

## 10. Production concerns
### Scaling
S3 tự động scale để xử lý hàng ngàn request mỗi giây. Tuy nhiên, nếu traffic cực lớn, nên đặt tên key theo cách phân tán để tránh "hot partition".

### Failure
Dữ liệu trong S3 được sao lưu mặc định qua ít nhất 3 Availability Zones (AZs). Sử dụng Cross-Region Replication (CRR) để bảo vệ dữ liệu nếu toàn bộ Region gặp sự cố.

### Monitoring
Sử dụng S3 Storage Lens để có cái nhìn tổng quan về lưu trữ và CloudWatch Metrics để theo dõi số lượng request, lỗi 4xx/5xx.

## 11. Common mistakes
- Mistake: Để Bucket ở chế độ Public Access một cách vô ý.
  Fix: Luôn bật tính năng "Block Public Access" trừ khi thực sự cần thiết cho static hosting.

- Mistake: Không sử dụng Lifecycle Policies cho dữ liệu cũ.
  Fix: Thiết lập quy tắc tự động chuyển dữ liệu sang S3 Glacier hoặc xóa sau một khoảng thời gian để tiết kiệm chi phí.

## 13. Interview
### Core Q&A
1. Q: S3 Storage Classes phổ biến nhất là gì?
   A: S3 Standard (truy cập thường xuyên), S3 Intelligent-Tiering (tự động tối ưu), S3 Standard-IA (truy cập không thường xuyên), và S3 Glacier (lưu trữ lâu dài, giá rẻ).

### Scenario
1. Q: Làm thế nào để cho phép một người dùng chưa đăng nhập tải một file riêng tư trong 15 phút?
   A: Tôi sẽ sử dụng **S3 Pre-signed URL**. URL này chứa thông tin xác thực tạm thời và sẽ hết hạn chính xác sau 15 phút.
